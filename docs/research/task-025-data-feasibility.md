## Sample and arithmetic proposal for approval

Initial Game Total research reuses **accepted reciprocal dated rows**, scoped to one of 2024–2026 and explicit REG or POST, with required matchup identity and the existing strict kickoff bound. Select newest N rows first, as Task 023 does. Missing scores remain visible unknown observations; do not fetch older games to backfill a market statistic. Report selected count, known-value count, unknown count and exclusions separately. A game with score data but no accepted team pair remains outside this population unless a later task explicitly approves a schedule-only population. A mean is SUM(known per-game values)/known-value count; zero known values means null, never zero.

For a proposed manual threshold T, compare the known value X exactly with Decimal: Over when X>T, Under when X<T, Push on equality. Spread uses selected-team margin + signed handicap, with zero a push. These are provisional retrospective comparisons of reported results. Return both side counts, pushes and unknowns; switching the selected side uses its corresponding server summary, not `100 − over`.

Proposed default frequency is hits / known-value count, **including pushes in that denominator**, with a visible push count. A separately labeled “excluding pushes” rate may return hits/(known-value count − pushes), null when all push. This matches neither every possible bookmaker rule nor an approved new business definition yet: approve the chosen display convention with Task 026. It deliberately makes the research's derived 67% non-push example explicit instead of silently adopting it. No price is needed to research manual lines; no price-based expected profit or model probability is proposed.

No threshold is fabricated. Without a user-entered line, return the history/mean and unavailable outcome/rate fields with `threshold_required`; counts must not pretend all observations lost. An explicitly user-confirmed stored game reference may seed manual entry later, labeled unverified. Missing per-event reference lines never exclude known score observations. Source-reference outcomes and selected-threshold outcomes are distinct objects/columns.

## Gates, not reasons to postpone the first slice

The next backend slice can compute full-game point histories and manual total outcomes from existing columns without a data import, chart library or paid odds. It does require explicit approval of the projection/threshold/sample/rate contract. Live database coverage and PostgreSQL runtime verification are acceptance checks, not facts established by this planning task. First-half, real team-total offers, verified closing quotes and advanced ranks remain unavailable independently of that slice. True completion-before-cutoff or as-published historical research still needs a separate evidence gate; label current chronological reconstructions honestly.
